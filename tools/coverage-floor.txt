# Coverage floors, one line per package: <import path> <percent, or none>.
#
# THE ONLY PLACE THIS NUMBER LIVES. It is deliberately not repeated in any
# document, because a number kept in two places starts disagreeing with itself
# the first time one of them is edited.
#
# HOW A FLOOR IS SET: the measured value rounded DOWN to a whole percent. The
# slack is there so an ordinary edit does not turn the gate red for a tenth of
# a point, and it is small enough that a branch quietly going untested still
# shows up.
#
# A FLOOR ONLY EVER RISES. Lowering one to turn a red run green is the owner's
# decision, not a way to get unblocked - the same rule the size ratchet follows.
# Raising one after coverage improves is ordinary work and welcome.
#
# TWO FLOORS WERE LOWERED ON 2026-10-14, BY THE OWNER, AND NOT FOR THE CODE.
# Go 1.27.0 and 1.27.1 counted some statements twice and reported coverage
# higher than it was (golang/go#81832, fixed in 1.27.2). Every floor set between
# 2026-09-01, when this module moved to 1.27.0, and that day was measured with
# that instrument. Two of them - proxyconf and proxyauth - fell below themselves
# on unchanged code and are now the corrected measurement rounded down. The rest
# still clear their floors, which means their slack is smaller than it was
# written as being, and nothing else about them changed.
#
# EVERY PACKAGE MUST APPEAR HERE. A package with no line is a finding, not a
# package with no floor. Without that rule the gate would quietly stop covering
# the tree as new directories appear, which is exactly how the layer guard would
# have failed if it did not report packages outside its map.
#
# WHAT THIS NUMBER IS NOT. Coverage measures which statements ran, never whether
# anything was asserted about them. A hundred percent with tests that stay green
# when the behaviour is broken is worth less than seventy with tests checked by
# the mutation register. This gate is a floor under the mutation register, not a
# substitute for it.
#
# MEASURED ON LINUX TOO, 2026-08-03, in WSL with the same Go version. Every
# package came out at or above the floor below, so these numbers are the lower
# bound of the two platforms rather than a Windows quirk - which is what a floor
# has to be. Two packages are well above it there and stay at the Windows number
# on purpose: privilege reaches 100 percent because the file Linux compiles is
# three lines, and output reaches 78.3 because the test about file mode bits is
# not skipped where mode bits mean something.
#
# THE PARAGRAPH ABOVE STOPPED BEING TRUE AND IS KEPT RATHER THAN EDITED, because
# how it went wrong is worth more than the corrected sentence. Measured on
# 2026-09-03 on both systems: internal/adapter/dns was at 91.4 percent on Windows
# and 75.8 in a container, against a floor of 90. The whole difference was
# nameservers_other.go - the POSIX read of resolv.conf - which no test had ever
# executed. So "the lower bound of the two platforms" was a claim about a
# measurement taken once, restated afterwards as a property of the file.
#
# IT STAYED HIDDEN FOR A REASON WORTH NAMING: on ubuntu the tests were failing
# EARLIER, so this gate never ran there at all. It surfaced only once the
# failures in front of it were fixed. A check that cannot run is not a check
# that passes, and nothing said which of the two was happening.
#
# The gap was closed by writing the tests, not by lowering the floor - lowering
# it would have taken the Windows side down with it, where the package was
# already above. OBS100.
#
# THE dns FLOOR STAYED AT 90 AFTERWARDS, AND THAT IS A DECISION RATHER THAN AN
# OVERSIGHT. Measured 2026-09-03 after the fix: 96.9 percent in the container,
# 91.4 on Windows. The rule at the top of this file would put the floor at 91 -
# the lower platform, rounded down - and that is exactly 0.4 points of slack on
# the platform that has none to spare. The Windows number comes from THIS
# machine, and internal/adapter/dns is the one package whose coverage depends on
# what the machine running it actually has: nameservers_windows.go walks the
# registry and the IP helper API, and a CI runner has different adapters. This
# gate prints a number only when it fails, so nobody has ever seen the runner's.
# Raising the floor on an unmeasured platform is how a green pipeline turns red
# for a reason nobody can reproduce - which is the failure this whole piece of
# work was undoing. Raise it once a Windows runner has reported a number.
#
# WHY IT EXISTS AT ALL, measured on 2026-08-03: internal/adapter/output sat at
# 54.5 percent while every guard in the repository was green, and the statements
# nobody had ever executed were the ones that clean up after a failed write -
# that is, the ones deciding whether this tool leaves litter in somebody's
# directory. Nothing reported it. Somebody had to go and look.

# The platform transport for those rules arrived 2026-09-06 with the second half
# of P8-K2, and its floor is the lowest in this file. THAT IS THE CONSEQUENCE OF
# A DESIGN RATHER THAN A GAP IN THE TESTING, and it is written here rather than
# left to be guessed at.
#
# internal/adapter/proxyconf calls somebody else's API and hands back strings.
# Everything that is text - the exception list rules, the scutil dictionary, the
# precedence between two spellings of one variable, every conversion of a
# platform reading into a lens - lives next door in internal/core/proxy, where it
# has no build tag, sits at 100 percent, and can be aimed at by the mutation
# register. What is left here needs a real machine.
#
# WHICH PLATFORM IS THE LOWER ONE IS MEASURED, NOT ASSUMED - OBS100, which cost a
# month of a floor that was true once. Measured 2026-09-06: Windows 84.5 percent
# and Linux 100. Windows compiles proxyconf_windows.go, whose two API calls are
# exercised against whatever this machine holds; Linux compiles a Read that
# returns nothing and a reason, which is tested exactly. So the floor is the
# Windows number rounded down, and Linux clears it with room to spare.
#
# MEASURED AGAIN 2026-10-14 UNDER GO 1.27.2: Windows 83.1 percent, 54 of 65
# statements, three runs alike. The 84.5 of September fits 60 of 71 - the same
# eleven statements unreached over a denominator the cover tool had inflated
# (golang/go#81832). That is arithmetic and the upstream report, not a rerun
# under 1.27.0. The floor is 83 by the owner's decision. Linux was not measured
# again that day.
#
# WHAT NO NUMBER HERE COVERS, said plainly: proxyconf_darwin.go. It is one line
# long, and it is one line long on purpose - every branch that line could get
# wrong was moved into proxyconf.go, which every platform compiles and every
# platform tests. The gate does not run on macOS at all (see ci.yml), so a floor
# would not have caught it either way. This is the narrowed remainder of OBS107.

# Asking a proxy whether it wants credentials arrived 2026-09-07 with P8-K3c.
#
# THE PACKAGE IS ONE FILE AND IT IS ON THE DIAL ALLOWLIST, which is why its tests
# drive a real listener rather than a seam: what this adapter has to get right is
# the shape of the bytes it puts on a wire and the way it reads the ones that
# come back, and neither of those is observable from in front of net. That also
# makes the number honest without a machine in a particular state - a loopback
# listener answering fixed bytes reaches every branch that decides anything.
#
# WHAT THE REMAINDER IS, said plainly rather than left to be guessed at. Three
# statements are not reached. Two are error paths that need the operating
# system to fail in a specific way: a write that fails on a socket the proxy
# accepted, and a dial error that is not a *net.OpError. Chasing either would
# mean a test that passes or fails depending on whose kernel it runs on, which is
# the opposite of what this gate is for. The third is the check for an empty
# scheme name in schemesOf, and no test can reach it: the piece is trimmed and
# not empty, so it never starts with the space or tab firstWord cuts on. Until
# 2026-10-14 this paragraph said two - it was written from reading the code, and
# the profile says three.
#
# WHICH PLATFORM IS THE LOWER ONE WAS ASKED RATHER THAN ASSUMED - OBS100, the note
# that cost a month of a floor which had been true once. Measured 2026-09-07:
# Windows 97.1 percent, and this gate clears the same floor inside the
# golang:1.27-alpine container. There is no build tag in this package, so both
# platforms compile the same single file and the two numbers have no reason to

#
# MEASURED AGAIN 2026-10-14 UNDER GO 1.27.2: 96.7 percent, 87 of 90 statements,
