# Shape ceilings, one line per dial: <dial> <number>.
#
# THE ONLY PLACE THESE NUMBERS LIVE. They are deliberately not repeated in any
# document, because a number kept in two places starts disagreeing with itself
# the first time one of them is edited - the same sentence coverage-floor.txt
# opens with, and for the same reason.
#
# EVERY NUMBER HERE IS THE MEASUREMENT, NOT A LIMIT ABOVE IT. The ceilings were
# frozen as measured on the day M1's last renderer landed, with no slack added,
# and since 2026-11-11 a second guard holds each number to exactly what the tree
# measures, in both directions. A number parked above the truth grants headroom
# nobody decided to grant - and that is how this file stood that day: the
# longest function was 82 lines under a ceiling of 84, and the longest file 1308
# under 1340. So shortening something comes with a chore, and it is meant to be
# routine: bring its number down in the same change.
#
# A NUMBER ONLY EVER FALLS. Lowering one after something is shortened is
# ordinary work and welcome. Raising one is the owner's decision, not a way to
# get unblocked - because at a size ratchet that move is especially tempting: it
# looks like tidying rather than like editing an expected value to make a test
# pass, and it is the same act.
#
# THE AXES. Production and tests have their own numbers, because they are two
# different measurements, not because tests are allowed more.
#   function, test-function, file, test-file - LINES OF CODE: lines that are
#     neither empty nor entirely comment. This project requires comments saying
#     WHY, so a measure counting them would be a ceiling on explanation.
#   depth, test-depth - how many blocks deep the deepest statement of a function
#     sits, counted the way a person sees it indented: an else-if chain is one
#     level, the cases of a switch sit at the switch's level.
#   branches - decision points: one for the way straight through, one for every
#     if, for, range, case with a condition, && and ||. Production only.
#   arguments - what a caller lines up, receiver not counted. Production only.
#
# WHY TWO NUMBERS PER AXIS. A ceiling on the single worst case catches one
# function growing to a record, and misses twenty functions growing by two lines
# each - which moves no maximum at all. The "-near-ceiling" counts are the second
# dial: how many things already stand in the band below the ceiling. Where each
# band starts is a rule, so it lives in the guard, as a fixed number rather than
# a share of the ceiling. These counts are measurements, so they live here.
#
# WHAT THESE NUMBERS ARE NOT. Length says nothing about readability. A short
# function can be unreadable, and a long table of test cases is often the
# clearest thing in a file - the top of the test list has been a table of cases
# on every measurement so far. This gate is a tripwire on drift, not a claim
# that anything under it is well written.
#
# The guard is internal/guard/size_test.go, and it runs in "go test ./...", so
# it is checked on every platform without a step of its own. Its log prints the
# worst sample of every axis and how many stand in each band.
